**コマンドコンテキスト**: Epic層の管理（エピック分解→ストーリー一括作成）

## 初回必須タスク

作業開始前に以下のファイルを必ず読み込み、厳守してください：
- @.claude/steering/story-structure.md - ディレクトリ構造とSSOT原則
- @.claude/steering/sub-agents.md - サブエージェント管理フロー
- @decomposer.md - ストーリー分解ロジック（本スキルのサブファイル）

## 責務

**Epic層のみ担当**（Story層は/implementコマンドが担当）

このコマンドは以下をオーケストレーションします：
1. **ローカルファイル操作**: エピック情報読取、ストーリーディレクトリ・ファイル一括作成
2. **@decomposer.md**: エピックのストーリー分解ロジック（スキル内サブファイル）

**責務境界**：
- エピック→ストーリー分解（@decomposer.mdのロジックに従い実行）
- エピックディレクトリ作成（@decomposer.mdのロジックに従い実行）
- epic.md生成（技術方針のみ生成、ストーリー一覧は空）
- ストーリーID自動採番（`specs/stories/S-*` をスキャンして最大番号+1）
- ストーリーディレクトリ・story.md・meta.json一括作成
- epic.mdにストーリー一覧を追記（採番済みIDを使用）
- ストーリーの設計・実装（/implementコマンドが担当）

## 入力

```
/epic-to-stories <エピック説明テキスト or エピックディレクトリパス> [追加指示]
```

**引数**：
- `<入力>` (必須): 以下のいずれか
  - **パターンA: ローカルファイルパス** - `specs/epics/E-1-xxx/epic.md` のようなエピックファイルのパス
  - **パターンB: 直接テキスト入力** - エピックの説明テキスト（例: 「HapicoMVP: 親がタスクを作成し、子どもが完了してコインを獲得する仕組み」）
- `[追加指示]` (任意): ユーザーからの追加要望・制約・方針
  - 例: 「モバイルファーストで設計」「既存DBスキーマを流用」「セキュリティ重視」

## 実行フロー

### Step 1: 入力検証

```
1. 引数チェック: エピック情報（ファイルパスまたはテキスト）が指定されているか確認
2. パターン判定:
   - ファイルパス形式（.mdで終わる、specs/で始まる等）→ パターンA
   - それ以外 → パターンB（直接テキスト入力）
3. エラー時:
   - エラーメッセージを表示
   - 使用例を提示
   - 処理を中断
```

### Step 2: エピック情報取得

```
パターンA（ファイルパス指定）:
1. 指定されたファイルをReadツールで読み込み
2. epicData（epicId, title, description, requirements）を抽出
3. エラーハンドリング:
   - ファイルが存在しない → エラーメッセージ表示、処理中断
   - ファイル形式不正 → エラーメッセージ表示、処理中断

パターンB（テキスト入力）:
1. ユーザー入力テキストをそのままepicDataとして使用
2. epicIdが未確定の場合:
   - specs/epics/E-* をGlobでスキャンし、最大番号+1で自動採番
```

### Step 3: ストーリー分解ロジック実行

**参照**: @decomposer.md

```
1. @decomposer.mdのロジックに従い分解を実行:
   - 入力:
     - epicData（Step 2の出力 - ローカルファイルまたはテキストから取得したエピック情報）
     - userRequest（ユーザーからの追加指示）
   - 処理内容（@decomposer.md参照）:
     - Phase 1: ストーリー分解（リリース単位、必要最小限）
     - Phase 2: エピック全体のアーキテクチャ方針策定
     - Phase 3: エピックディレクトリ作成（specs/epics/のみ）
     - Phase 4: epic.md生成（技術方針のみ、ストーリー一覧は空）
   - 出力: storiesData (epicId, epicDirectory, stories[{title, summary, detailedContent}], implementationOrder[])

2. エラーハンドリング:
   - ディレクトリ作成失敗 → エラーメッセージ表示、処理中断
```

**重要な変更点**:
- ストーリーディレクトリはこのステップでは作成**しない**（Step 5で一括作成）
- meta.jsonもこのステップでは作成**しない**（Step 5で一括作成）
- stories配列にはstoryIdは含まれない（Step 5で自動採番するため）
- stories配列には`summary`（簡潔な概要）と`detailedContent`（詳細な要件）が含まれる

### Step 4: ユーザー確認（分解結果の承認）

```
1. decomposerの出力を表示:
   - エピックID、タイトル
   - 生成されたストーリー一覧（タイトル、概要）
   - 実装順序の推奨
   - ディレクトリ構造

2. ユーザーに確認を求める:
   「このストーリー分解で進めてよろしいですか？ (yes/no)」

3. ユーザー応答のハンドリング:
   - "yes" または "y": Step 5へ進む
   - "no" または "n": 処理をキャンセル、メッセージ表示して終了
   - その他: 再度確認を求める
```

### Step 5: ストーリー一括作成（ローカル）

```
1. ID自動採番:
   - specs/stories/S-* をGlobでスキャンし、既存ディレクトリ名から最大番号を抽出
   - 最大番号+1から連番で各ストーリーにIDを割り当て
   - 例: 既存がS-33まで → 新規はS-34, S-35, ...

2. 各ストーリーについて:
   a. ディレクトリ作成:
      `specs/stories/{S-XX}-{title}/`
      例: `specs/stories/S-34-parent-task-creation/`

   b. story.md作成:
      - decomposerが生成したdetailedContentをそのまま書き込み
      - 省略・要約は一切行わない

   c. meta.json作成:
      {
        "story_id": "S-XX",
        "epic_id": "E-Y",
        "parent_story_id": "",
        "status": "not_started",
        "github_pr_url": "",
        "github_branch": ""
      }

3. エラーハンドリング:
   - ディレクトリ作成失敗 → エラーメッセージ表示、処理中断
   - 部分的成功 → 成功/失敗した項目を明示、ユーザーに報告
```

**detailedContentの必須チェック**:
- decomposerが生成した`detailedContent`（詳細な要件定義）を**必ず完全な形で**story.mdに書き込むこと

**厳禁行為**:
- detailedContentを「(省略)」などと省略して書き込むこと
- summaryだけを書き込んでdetailedContentを書き込まないこと
- detailedContentの一部だけを書き込むこと

**detailedContentの検証**:
- 「# 要件概要」「# 機能要件の詳細」「# 技術要件」などのセクションを含むはず
- 省略されている場合は即座にエラーとして処理を中断すること

### Step 5.5: epic.mdにストーリー一覧を追記

```
1. `specs/epics/{EPIC_ID}-{title}/epic.md` を読み込み
2. 「## このエピックのストーリー」セクションを見つける
3. テンプレートのコメント行を削除
4. 各ストーリーについて以下の形式で追記:
   - [{S-XX}](../../stories/{S-XX}-{title}/) - {summary}
   例: - [S-34](../../stories/S-34-parent-task-creation/) - 親がタスクを作成・配布する画面...
5. epic.mdを保存
```

### Step 6: 結果表示

```
1. 完了メッセージを表示:
   - エピックID、タイトル
   - 生成されたストーリー数
   - 各ストーリーのIDとディレクトリパス
   - 実装順序の推奨

2. 次のアクションを案内:
   「各ストーリーの実装は以下のコマンドで開始できます：」
   /implement specs/stories/{S-XX}-{title}/
```

## エラーハンドリング

### 入力未指定

```
エラー検出時:
1. エラーメッセージを表示:
   エピック情報が指定されていません。

2. 使用例を提示:
   使用例:
   /epic-to-stories specs/epics/E-1-authentication-system/epic.md
   /epic-to-stories 「HapicoMVP: 親がタスクを作成し、子どもが完了してコインを獲得する仕組み」

3. 処理を中断
```

### ファイル読取失敗

```
エラー検出時:
1. エラーメッセージを表示:
   エピック情報の読み取りに失敗しました。

2. 対処方法を案内:
   - ファイルパスが正しいか確認してください
   - ファイルが存在するか確認してください

3. 処理を中断
```

### ユーザーがキャンセル

```
ユーザーが"no"を選択した場合:
1. キャンセルメッセージを表示:
   ストーリー分解をキャンセルしました。

2. 作成済みのディレクトリ構造を案内:
   以下のディレクトリは作成済みです：
   - specs/epics/{EPIC_ID}/

   ストーリーディレクトリは作成されていません。

3. 処理を終了
```

### 部分的成功（一部のストーリー作成失敗）

```
一部のストーリー作成に失敗した場合:
1. 警告メッセージを表示:
   一部のストーリー作成に失敗しました。

2. 成功/失敗の詳細を表示:
   成功したストーリー (3件):
   - S-34: parent-task-creation
   - S-35: child-task-completion
   - S-36: coin-distribution

   失敗したストーリー (2件):
   - S-37: reward-shop (エラー: ディレクトリ作成失敗)
   - S-38: analytics-dashboard (エラー: ファイル書き込み失敗)

3. 対処方法を案内:
   失敗したストーリーは手動で作成するか、/epic-to-storiesコマンドを再実行してください。

4. 処理を完了（成功したストーリーは有効）
```

## 使用例

### 基本的な使用例（ファイルパス指定）

```
入力:
/epic-to-stories specs/epics/E-1-authentication-system/epic.md

実行内容:
1. epic.mdファイル読み込み
2. 5つのストーリーに分解（decomposer）
3. ユーザー確認（承認）
4. ストーリーID自動採番（S-* スキャン）
5. 5つのストーリーディレクトリ・story.md・meta.json一括作成
6. epic.mdにストーリー一覧を追記

出力:
エピック分解完了

**エピック情報**:
- エピックID: E-1
- タイトル: Authentication System
- ディレクトリ: `specs/epics/E-1-authentication-system/`

**生成されたストーリー** (5件):
1. S-34: user-registration
   - ディレクトリ: `specs/stories/S-34-user-registration/`

2. S-35: user-login
   - ディレクトリ: `specs/stories/S-35-user-login/`

...

**実装順序の推奨**:
1. S-34 - 基盤となるユーザー登録機能
2. S-35 - ログイン機能（登録機能に依存）
3. S-36 - セッション管理（ログイン機能に依存）
...

**次のアクション**:
各ストーリーの実装は以下のコマンドで開始できます:
```
/implement specs/stories/S-34-user-registration/
```
```

### 基本的な使用例（テキスト入力）

```

/epic-to-stories 「HapicoMVP: 親がタスクを作成し、子どもが完了してコインを獲得、報酬と交換する仕組み」

4. ユーザー確認（承認）
5. ストーリーID自動採番（S-* スキャン）
6. 4つのストーリーディレクトリ・story.md・meta.json一括作成
7. epic.mdにストーリー一覧を追記

出力:
エピック分解完了

**エピック情報**:
- エピックID: E-1
- タイトル: hapico-mvp
- ディレクトリ: `specs/epics/E-1-hapico-mvp/`

**生成されたストーリー** (4件):
1. S-1: parent-task-creation
   - ディレクトリ: `specs/stories/S-1-parent-task-creation/`
...
```

### キャンセルの例

```
入力:
/epic-to-stories specs/epics/E-2-payment-integration/epic.md

実行内容:
1. epic.mdファイル読み込み
2. 3つのストーリーに分解
3. ユーザー確認（拒否）

出力:
ストーリー分解をキャンセルしました。

以下のディレクトリは作成済みです：
- specs/epics/E-2-payment-integration/

ストーリーディレクトリは作成されていません。

再度分解を実行する場合は、/epic-to-storiesコマンドを実行してください。
```

## 品質基準

### 必須条件
- [ ] 入力（ファイルパスまたはテキスト）が正しく検証されること
- [ ] ローカルファイル読み取りが正常に動作すること
- [ ] decomposerが正常に実行されること（エピックディレクトリのみ作成）
- [ ] ユーザー確認が適切に動作すること（yes/no判定）
- [ ] ストーリーIDが正しく自動採番されること（S-* スキャン、最大番号+1）
- [ ] ストーリーディレクトリが正しく作成されること
- [ ] story.mdにdetailedContentが省略なく完全に書き込まれること
- [ ] meta.jsonが正しく作成されること（story_id, epic_id, status等）
- [ ] epic.mdのストーリー一覧が正しく更新されること（採番済みIDを使用）
- [ ] 結果表示にストーリーIDとディレクトリパスが正しく含まれること

### 推奨条件
- [ ] エラーメッセージがわかりやすく、対処方法が明確であること
- [ ] 部分的成功時に成功/失敗の詳細が明示されること
- [ ] 次のアクション（/implementコマンド）が明確に案内されること
