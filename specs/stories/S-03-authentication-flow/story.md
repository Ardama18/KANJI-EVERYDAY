# S-03: 認証フロー

# 要件概要

## 目的
- Supabase Auth を使ったメール/パスワード認証フロー（サインアップ・ログイン・ログアウト）を実装する
- 認証ミドルウェアにより未認証ユーザーをログインページへリダイレクトする
- サインアップ時に `users_profile` レコードを自動作成する

## 解決する課題
- ユーザーがアカウントを作成し、ログインして自分のデータにアクセスできるようにする
- 認証済みルートの保護（未認証ユーザーのブロック）
- RLS が正しく機能するための認証セッション管理

# 機能要件の詳細

## 1. サインアップ

### フロー
1. ユーザーがサインアップページにアクセス
2. メールアドレスとパスワード、表示名を入力
3. 「アカウントを作成」ボタンをタップ
4. Supabase Auth でアカウント作成
5. `users_profile` にレコードを自動作成（display_name, timezone='Asia/Tokyo'）
6. デッキ一覧ページ（`/decks`）へリダイレクト

### バリデーション
- メールアドレス: 必須、メール形式
- パスワード: 必須、8文字以上
- 表示名: 必須、1〜20文字

### エラーケース
- メールアドレス重複: 「このメールアドレスは既に登録されています」
- パスワード要件不足: 「パスワードは8文字以上で入力してください」
- サーバーエラー: 「アカウントの作成に失敗しました。もう一度お試しください」

## 2. ログイン

### フロー
1. ユーザーがログインページにアクセス
2. メールアドレスとパスワードを入力
3. 「ログイン」ボタンをタップ
4. Supabase Auth で認証
5. 成功時: デッキ一覧ページ（`/decks`）へリダイレクト
6. 失敗時: エラーメッセージを表示

### バリデーション
- メールアドレス: 必須、メール形式
- パスワード: 必須

### エラーケース
- 認証失敗: 「メールアドレスまたはパスワードが正しくありません」
- サーバーエラー: 「ログインに失敗しました。もう一度お試しください」

## 3. ログアウト

### フロー
1. ユーザーがログアウトアクションを実行（ヘッダーメニュー等）
2. Supabase Auth でセッション破棄
3. ログインページ（`/login`）へリダイレクト

## 4. 認証ミドルウェア

### 動作
- Next.js Middleware（`middleware.ts`）で全リクエストの認証状態をチェック
- Supabase の `getSession()` でセッションを検証し、Cookie を更新
- 未認証ユーザーが保護ルート（`/decks`, `/decks/*`）にアクセスした場合、`/login` へリダイレクト
- 認証済みユーザーが `/login`, `/signup` にアクセスした場合、`/decks` へリダイレクト

### 公開ルート（認証不要）
- `/`: トップページ
- `/login`: ログインページ
- `/signup`: サインアップページ

### 保護ルート（認証必須）
- `/decks`: デッキ一覧
- `/decks/[deckId]`: デッキ概要
- `/decks/[deckId]/study`: 学習画面

## 5. users_profile 自動作成

### 方法
- サインアップの Server Action 内で、Supabase Auth のアカウント作成成功後に `users_profile` へ INSERT
- トランザクション的な整合性: Auth 成功 → Profile INSERT。Profile INSERT 失敗時はエラーを表示（Auth アカウントは作成済みなので、次回ログイン時にリカバリ）

### リカバリ
- ログイン時に `users_profile` が存在しない場合、自動作成する（サインアップ時の INSERT が失敗したケースの救済）

## 6. 認証済みレイアウト

### 構成
- `app/(auth)/layout.tsx`: 認証済みユーザー用レイアウト
  - ヘッダー: アプリ名「まいにち漢字」+ ログアウトボタン
  - コンテンツエリア: 子コンポーネント描画
- `app/(auth)/decks/page.tsx`: デッキ一覧（E-02 でUI実装、ここではレイアウト枠のみ）

# 技術要件

## Server Actions

### `signUp(formData: FormData)`
- `src/actions/auth-actions.ts` に定義
- Supabase Auth の `signUp()` 呼び出し
- 成功時: `users_profile` に INSERT → `/decks` へリダイレクト
- 失敗時: エラーメッセージを返す

### `signIn(formData: FormData)`
- Supabase Auth の `signInWithPassword()` 呼び出し
- 成功時: `/decks` へリダイレクト
- 失敗時: エラーメッセージを返す

### `signOut()`
- Supabase Auth の `signOut()` 呼び出し
- `/login` へリダイレクト

## Middleware（`middleware.ts`）
- `@supabase/ssr` の `createServerClient` を使用して Middleware 内で Supabase セッションを検証
- Cookie の読み書きを行い、セッションをリフレッシュ
- matcher 設定で静的アセット（`_next/static`, `_next/image`, `favicon.ico`）を除外

## セキュリティ要件
- パスワードは Supabase Auth がハッシュ化して保存（アプリ側では平文を保持しない）
- CSRF 対策: Server Actions は Next.js のビルトイン CSRF 保護を利用
- セッション Cookie は HttpOnly, Secure, SameSite 設定

# UIデザイン仕様

## ログインページ（`/login`）
- 画面中央にフォームを配置
- フィールド: メールアドレス（`type="email"`）、パスワード（`type="password"`）
- ボタン: 「ログイン」（プライマリ）
- リンク: 「アカウントを作成」→ `/signup`
- エラーメッセージ: フォーム上部に赤色で表示

## サインアップページ（`/signup`）
- 画面中央にフォームを配置
- フィールド: 表示名、メールアドレス、パスワード
- ボタン: 「アカウントを作成」（プライマリ）
- リンク: 「ログインはこちら」→ `/login`
- エラーメッセージ: フォーム上部に赤色で表示

## 共通
- スマホ優先レイアウト（最大幅 `max-w-md` 程度）
- 入力フィールドは十分な高さ（タッチしやすいサイズ、最小 48px）
- ボタンは全幅（`w-full`）で親指操作しやすいサイズ
