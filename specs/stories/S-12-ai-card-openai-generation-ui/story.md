# S-12: アプリ内OpenAIカード生成UI

## ユーザーストーリー

保護者・先生として、テキスト指示や教材画像からR1/W1カード案をアプリ内で作成し、内容と注意事項を確認してから自分のデッキへ登録したい。なぜなら、子どもの苦手な漢字に合う練習カードを、安全かつ少ない手間で追加したいから。

## 解決する課題

- AIカード登録基盤は存在するが、ログインユーザーがアプリ内からカード案を生成・確認・登録する画面がない。
- AI出力には誤り、個人情報、著作権上の問題が含まれ得るため、大人が全カードを確認して明示的に確定する境界が必要である。
- 長時間処理中の再読み込みや部分失敗でも、登録状況を見失わない導線が必要である。

## スコープ

### 対象

- デッキ詳細からの「AIでカードを作る」導線
- テキスト指示、教材画像、R1/W1/both、tag、illustration方式の入力
- OpenAIによるR1/W1案の生成と入力・出力moderation
- 生成案の編集・除外、警告確認、明示的commit
- queued以降の進捗表示、`batchId`によるpoll、再読み込み復元
- モバイル幅・キーボード・label/error関連付けを含むアクセシビリティ
- feature flagによる安全な停止

### 対象外

- PDF、R2/W2、一般問題形式
- BYOK
- 大人の確認を省略した登録
- S-10/S-11基盤の置換または再構築
- AIカード一覧・編集・削除管理画面、Remote MCP、OAuth

## 受入条件

1. テキストのみ、または教材source画像付きで、R1/W1カード案を生成できる。
2. `both`は同一conceptの表裏を交換したR1/W1の2枚を作り、1〜50枚上限は展開後に適用される。
3. Structured Outputs不一致、refusal、moderation拒否、provider障害が区別して表示される。
4. ユーザーはカード案を編集・除外でき、警告確認なしでは登録できない。
5. preview tokenの改ざん・期限切れ・内容差し替えは拒否される。
6. source画像は処理終了後に削除され、異常終了時も24時間清掃対象となる。
7. 360px幅で横スクロールせず、キーボード操作とlabel/error関連付けが成立する。
8. `npm run check`が成功し、既存デッキ・学習画面に回帰がない。

## ロールバック

`AI_CARD_IMPORT_ENABLED=false`で新規作成導線と生成・commit操作を停止する。既存カードと既存batchの状態参照は保持する。
